# API reference: domain-aware and verifiable operations

This page covers the domain-aware, explainable, and certificate APIs added on
top of the core CAS. It is not an exhaustive reference for every public export;
TypeScript declaration files are generated by `npm run build`.
The library build does not generate source maps and removes older generated
source maps, their references, and JavaScript and declarations without a
corresponding TypeScript source from `dist/src`.

## Numerical precision and guarantees

Exact symbolic integers and rationals remain exact until passed to a numerical
API. Choose the numerical API according to the guarantee required:

| API | Precision model | Guarantee |
| --- | --- | --- |
| `evaluate`, `numericalDerivative`, `integrateNumerically`, `evaluateComplex` | JavaScript `number` (IEEE-754 binary64) | Approximate results, typically about 15–16 significant decimal digits. There is no general error bound; cancellation, rounding, overflow, and underflow may affect values. |
| `evaluateDecimal`, `evaluateComplexDecimal`, `NumericalEngine.evaluate` / `.evaluateComplex` | BigInt-backed decimal; default 50 significant digits, scalar range 2–10,000 | Rounded approximations, not certified enclosures. Pass decimal strings when input digits must not first be rounded by JavaScript `number`. |
| Decimal numerical calculus and general decimal root finding | BigInt-backed decimal; default 50, supported range 2–1,000 digits | `estimatedError` and `converged` describe estimator/stopping behavior, not a formal error proof. |
| `evaluateDecimalInterval` / `NumericalEngine.evaluateInterval` | Outward-rounded intervals; default 50, supported range 2–1,000 digits | Encloses exact values for the documented supported real-expression subset. Dependency can widen results; unsupported functions or intervals crossing singularities are rejected. |

Binary64 exactly represents every integer only through
`Number.MAX_SAFE_INTEGER` (`2^53 - 1`). Non-finite results are rejected, but
finite rounding and underflow to zero are not necessarily reported.

`numericalDerivative` prefers symbolic differentiation and falls back to finite
differences. `integrateNumerically` uses adaptive Simpson quadrature; decimal
integration compares 16- and 32-point Gauss–Legendre estimates. Their error
fields are estimates, not rigorous bounds. Numeric bisection and hybrid solvers
need a sign-changing bracket and assume continuity; Newton is a local method.
They do not prove uniqueness or find all roots. `converged: true` means the
method met its stopping criterion, not that a formal certificate was produced.

For exact root counts, `solvePolynomialNumericallyDecimal` uses Sturm
arithmetic and exact rational isolating intervals for univariate rational
polynomials (degree 24 by default, configurable up to 64). Its decimal root
values remain approximations. `certifyRealRoots` certifies only within the
finite search interval supplied: exact polynomials use Sturm analysis,
including multiple roots; supported non-polynomial expressions use a
conservative interval method for simple roots and may return `partial` with
unresolved regions.

Some deliberate argument limits are: scalar decimal `exp`, `|x| <= 10,000`;
scalar decimal `sin`/`cos`/`tan`, `|x| <= 10^12`; and certified interval
trigonometry, `|x| <= 10^30`. Interval π certification is limited to 988
digits, and trigonometric argument reduction can impose a lower effective
precision depending on argument size. An error, `partial`, or `unsupported`
status is not a successful numeric answer.

## Parsing and domain preservation

```ts
parseWithDomain(source: string): DomainSimplificationResult
solveWithDomain(
  input: Expr | DomainSimplificationResult,
  variable: string,
): DomainEquationSolveResult
solvePolynomialSystemWithDomain(
  equations: readonly DomainPolynomialEquation[],
  variables: readonly string[],
): DomainPolynomialSystemSolveResult
```

`parseWithDomain` retains the source structure while identifying restrictions
that canonical parsing might erase. Its result has `status`, an optional
simplified `expression`, carried `conditions`, and an optional `message`.
Conditions use `nonzero`, `positive`, or `nonnegative`.

Unary domain-aware transformations accept a `DomainSimplificationResult`:
`substituteWithDomain`, `differentiateWithDomain`, `expandWithDomain`,
`factorWithDomain`, `integrateWithDomain`, and `transformWithDomain`.
Use `combineWithDomain(inputs, combine)` to compose multiple independently
parsed expressions while retaining conditions from every operand.
Substitution that makes a condition numerically false returns `undefined`
status. Solvers report `solutions`, `excludedSolutions`, and
`undeterminedSolutions`; symbolic conditions that cannot be decided are not
silently treated as true.

`evaluateWithDomain` returns a numeric value only when carried conditions are
verified; near floating-point boundaries it returns `partial`. `limitWithDomain`
and the series wrappers retain the original conditions and report whether the
point is in the source domain. If inherited restrictions may constrain the
approach to a limit or local expansion, the result is marked `partial` rather
than claiming the transformed expression represents the source everywhere.
`analyzeContinuityWithDomain` likewise downgrades classifications when carried
restrictions are not represented in the simplified expression.

```ts
combineWithDomain(inputs: readonly DomainSimplificationResult[], combine: DomainExpressionCombine)
evaluateWithDomain(input: Expr | DomainSimplificationResult, bindings?: NumericBindings)
limitWithDomain(input, variable, point, direction?): DomainLimitResult
seriesWithDomain(input, variable, point, order?): DomainSeriesResult
taylorSeriesWithDomain(input, variable, point, order?): DomainSeriesResult
laurentSeriesWithDomain(input, variable, point, order?): DomainSeriesResult
analyzeContinuityWithDomain(input, variable, point, options?): DomainContinuityResult
```

The original `parse` and algebra APIs retain their existing canonical behavior.
Use the domain-aware entry points when source restrictions matter.

## Trigonometric and power simplification

The existing `simplify(expression)` API handles the Pythagorean identity for
matching sine and cosine arguments, including scaled forms and rearrangements
such as `1 - cos(x)^2`. It also evaluates sine and cosine exactly for common
rational multiples of `pi`, including multiples of `pi/6`, `pi/4`, `pi/3`, and
`pi/2`. Other exact angles remain symbolic unless covered by these rules. It
combines powers with a shared integer exponent, combines powers of known-positive
bases (`pi`, `E`, positive exact numbers, and `exp(...)`), and denests nested
integer powers or powers of known-positive bases. It simplifies `sqrt(q)` and
`q^(1/2)` to an exact rational when the non-negative rational `q` is a perfect
square; other square roots remain symbolic. It is not a general
trigonometric identity prover and does not infer positivity assumptions for
symbols.

The existing `expand(expression)` API rewrites `cos(2*a)` as
`cos(a)^2 - sin(a)^2`, distributes nonzero integer powers over products, and
splits sums in the exponent only for bases known to be positive. These APIs
deliberately avoid branch-sensitive rewrites such as `(x^2)^(1/2) -> x` or
`x^(a+b) -> x^a*x^b` for an unrestricted symbolic base.

## Explanations

### Principal-power equations

`solve` and `solveEquation` support `a*x^sqrt(r)+b=0` when `a` and `b` are
exact rationals, `a` is nonzero, `0 < r < 4` is rational, and `-b/a` is
positive. The result is the unique solution on the principal complex-power
branch and is positive real. Cases outside these bounds remain unsupported;
in particular, larger exponents can have additional complex solutions.
`solveWithSteps` reports `principal-power-inversion`, but independent
verification and proof certificates for these solutions are not yet supported.
Real-domain restrictions that cannot be checked remain undetermined;
`solvePiecewiseEquation` reports `partial` for this method.

### Polynomial equations with symbolic parameters

`solve` and `solveEquation` support linear and quadratic equations with
rational coefficients of the variable and a constant term that is a
polynomial in other symbols, including parameters and `pi` or `E`. For example,
`x^2 - y = 0` has the exact complex roots `sqrt(y)` and `-sqrt(y)`, using the
principal square root. They coincide at `y = 0`; for real `y` they are real
only when `y >= 0`. Symbolic coefficients of the variable and higher degrees
with parameters remain unsupported. `solveWithDomain`,
`solveWithProof`, and `solvePiecewiseEquation` do not yet filter or certify
such solutions over the real domain; the latter reports `partial`.

### Quartic polynomial roots

For exact rational univariate polynomials, `solve` and `solveEquation` solve
linear, quadratic, and quartic factors found by the rational factorization.
Quartic roots are exact radical expressions using principal complex square
roots and principal complex powers with exponent `1/3`; numerical evaluation
can be sensitive to rounding. Factorization can leave other factors, including
irreducible cubics, unresolved. Check `status` for `finite`, `partial`, or
`unsupported`, rather than treating an empty list as proof of no roots.

Results containing quartic radical solutions have `method: "quartic-formula"`.
Independent verification of these expressions is not yet supported by
`verifyEquationSolveExplanation`; `solveWithDomain` returns them as
undetermined and `solveWithProof` reports `unsupported`. Separately,
`solveWithCertificates` can certify the complete set of real roots within its
documented limits. `solvePiecewiseEquation` reports `partial` for branches
requiring quartic radicals because it cannot reliably filter them as real roots.

### Trigonometric equations

`solve` and `solveEquation` support real equations of the form
`a*sin(b*x+c)+d=0` or `a*cos(b*x+c)+d=0` when `a`, `b`, `c`, and `d`
are exact rationals, `a` and `b` are nonzero, and the target sine or cosine
value is `-1`, `0`, or `1`. A result with `status: "infinite"` contains solution-family
expressions in `solutions` and an integer `parameter` describing their
parameter. Other trigonometric equations remain `unsupported`. These families
describe real roots; they are not polynomial root certificates. Domain-aware
solving reports `unsupported` if it must filter an infinite family against
carried domain restrictions.

```ts
differentiateWithSteps(expression: Expr, variable: string): DifferentiationResult
verifyDifferentiationExplanation(expression: Expr, variable: string, explanation: DifferentiationResult)
solveWithSteps(expression: Expr, variable: string): EquationSolveExplanation
verifyEquationSolveExplanation(expression: Expr, variable: string, explanation: EquationSolveExplanation)
factorWithSteps(expression: Expr, variable?: string): FactorizationExplanation
verifyFactorizationExplanation(expression: Expr, explanation: FactorizationExplanation)
integrateWithSteps(expression: Expr, variable: string): IntegrationExplanation
verifyIntegrationExplanation(expression: Expr, explanation: IntegrationExplanation, variable: string)
```

These APIs return the ordinary result plus structured method/rule identifiers.
Differentiation and integration steps have `id` and `parentId` fields; the
integration trace records nested sums, constant factors, and supported
integration-by-parts subproblems. The verification functions replay the
explanation; differentiation and integration additionally recalculate each
derivative claim, factorization checks the exact polynomial identity, and
equation solving checks reported roots against the input equation.
These checks do not constitute formal proof objects.

`toLearningExplanation(trace, options?)` converts one of these existing traces
into display-ready steps with a readable rule title, why it applies, necessary
conditions, and the original expression/result data. It supports
differentiation, factorization, integration, and equation-solving traces.
Differentiation requires `options.variable`; parent-linked integration and
differentiation steps retain their IDs for tree rendering. The text describes
the mathematical conditions for each rule; it does not assert that every
condition has been proven for a particular input.

```ts
const trace = differentiateWithSteps(parse("ln(x)"), "x");
const lesson = toLearningExplanation(trace, { variable: "x" });
lesson.steps.forEach(step => {
  console.log(step.title, step.why, step.conditions);
});
```

`limit` already includes the selected `method` and `lHopitalSteps` in its
`LimitResult`.

## Proof-carrying calculations

```ts
differentiateWithProof(input: Expr | DomainSimplificationResult, variable: string)
factorWithProof(input: Expr | DomainSimplificationResult, variable?: string)
integrateWithProof(input: Expr | DomainSimplificationResult, variable: string)
solveWithProof(input: Expr | DomainSimplificationResult, variable: string)
verifyProofCarryingResult(value: unknown, expectedInput?: Expr | DomainSimplificationResult)
```

Successful results are JSON-serializable and bundle the input, carried domain
conditions, algorithm trace, result, and a checkable identity or certificate.
Verification replays the operation and checks its result; equation solving also
includes a certificate for the complete distinct real-root set and records
domain-excluded or undecidable candidates. Unsupported cases return an
`unsupported` status instead of an unverifiable result.

These are machine-checkable algebraic checks, not formal proofs in a proof
assistant. Without `expectedInput`, verification checks the calculation under
the domain conditions embedded in the object; it does not establish where those
assumptions came from. Pass the original expression or domain-aware parse result
to bind both the expression and assumptions to the intended input.

## Certificates

### Real roots

```ts
createPolynomialRootCertificate(
  expression: Expr,
  variable: string,
  options?: PolynomialRootCertificateOptions,
): PolynomialRootCertificateCreationResult
verifyPolynomialRootCertificate(
  certificate: unknown,
  expectedExpression?: Expr,
): PolynomialRootCertificateVerificationResult
```

Certifies distinct real roots and multiplicities of a univariate rational
polynomial using exact Sturm arithmetic. The default maximum degree is 24;
`maxDegree` can be set up to 64.

### Polynomial inequalities

`createPolynomialInequalityCertificate(expression, variable, relation)` and
`verifyPolynomialInequalityCertificate(certificate, expectedExpression?)`
certify sign cells for univariate rational-polynomial inequalities. The
certificate includes exact root intervals and rational witnesses. It does not
support general rational-function inequalities.

### Linear systems

`createLinearSystemCertificate(equations, variables)` returns a certificate
only for a unique exact rational linear solution. Its verifier checks exact
residuals and recomputes full column rank. Limits: 128 variables and 512
equations.

### Polynomial-system certificates

`createPolynomialSystemWitnessCertificate(equations, variables)` serializes
the finite points returned by the supported two-variable polynomial-system
solver. `verifyPolynomialSystemWitnessCertificate` checks every listed point
against every equation using exact expression arithmetic.

This is a witness certificate and does not claim that its list is exhaustive.
`createPolynomialSystemCompletenessCertificate` additionally supports systems
where at least one equation is non-constant linear and eliminating one variable
reduces the other equation to a univariate polynomial of degree at most two.
This includes systems of two linear equations. The verifier binds to the
expected equations and variables, verifies a complete Sturm root-count
certificate for the reduced polynomial, and checks a distinct exact solution
witness for each real root. An identically zero reduced equation is reported as
an infinite solution set instead of issuing a finite certificate; a nonzero
constant equation can certify an empty set directly. This is a real-solution
completeness certificate, not a claim about complex solutions.

### Antiderivatives

```ts
createAntiderivativeCertificate(
  integrand: Expr,
  variable: string,
  candidate?: Expr,
): AntiderivativeCertificateCreationResult
verifyAntiderivativeCertificate(
  certificate: unknown,
  expectedIntegrand?: Expr,
): AntiderivativeCertificateVerificationResult
```

The verifier reparses the exact stored expressions, differentiates the
antiderivative, and checks that the residual simplifies to zero. This certifies
the identity over the common domain, not domain equivalence or a formal
calculus derivation.

### Unified certificate dispatch

`verifyCertificate(kind, certificate, context?)` dispatches to the checker for
`exact-polynomial-root`, `polynomial-root`, `polynomial-inequality`,
`linear-system`, `polynomial-system-complete`, `polynomial-system-witness`,
or `antiderivative`.
The optional context binds the certificate to an expected expression,
integrand, equations, or variable list where supported.

## Continuous checks

- `npm run test:all`: TypeScript build and full Vitest suite.
- `npm run test:oracle`: compare representative operations with frozen expected
  outputs generated by SymPy 1.12. This snapshot test does not require Python or
  a SymPy dependency in CI.
- `npm run validate:domain-helpers`: domain-helper smoke checks.
- `npm run benchmark`: deterministic benchmark workloads; set
  `BENCHMARK_OUTPUT=/path/report.json` for machine-readable output.

GitHub Actions runs correctness checks on Node.js 20 and 22 and benchmarks on
Node.js 22. CI uses generous per-case median budgets to catch severe slowdowns;
benchmark artifacts are retained for 30 days.
